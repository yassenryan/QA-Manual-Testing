## 📌 Overview

This project focuses on testing the **New Customer Module** based on the provided **Software Requirements Specification (SRS)**.

The objective was to analyze requirements, design structured **manual test cases**, and execute them across **four different versions** to verify system behavior and validation rules.

All test cases were executed to validate **input validation, business rules, and system responses** for both valid and invalid scenarios.

---

## 🎯 Objectives

- Convert **SRS requirements** into structured **manual test cases**
- Validate system behavior against defined **functional rules**
- Execute test cases across **4 different versions**
- Perform **positive and negative testing**
- Identify inconsistencies across versions
- Practice **real-world QA documentation**
- Strengthen **requirement analysis and execution skills**

---

## 🧪 Testing Techniques Used

- Equivalence Partitioning
- Boundary Value Analysis (BVA)
- Positive Testing
- Negative Testing
- Input Validation Testing
- Basic Security Testing
- Test Execution & Result Validation

## 📂 Test Case Structure

Each test case includes:

- Test Suite
- Test Case ID
- Test Scenario / Title
- Preconditions
- Test Steps
- Test Data
- Expected Result
- Actual Result
- Status (Pass / Fail)
